# Scam-text classifier: data, protocol, results

Satya's text check (`src/satyapan/textrisk/`) reads e-mails, SMS/WhatsApp text and live-call
transcripts and emits `TEXT_SCAM_LIKELY` when a message reads like a scam. It is **style
evidence**: the policy table caps it at VERIFY, so it can make Satya ask for a call-back, never
block a payment on its own, and it never lowers a band. This page is the benchmark behind it.
Reproduce: `python -m research.run_all text` (results in `results/text_benchmark.md`,
`results/text_neardup.md`, `results/text_eval_manifest.json`).

## 1. Model (what ships)

1. **De-obfuscation** (`normalize.py`): NFKC; zero-width and other invisible characters removed;
   Cyrillic/Greek/Cherokee look-alikes folded to Latin inside mostly-Latin words only (real
   Hindi/Russian words untouched); leetspeak folded inside words that also have letters
   ("acc0unt" → "account", but "₹500", "2026", "1st" stay); spaced-out letters joined
   ("O T P" → "OTP").
2. **Features** (`features.py`): word 1–2-grams + character 2–5-grams inside word boundaries,
   hashed with CRC-32 into 2^20 signed buckets; sublinear tf; IDF; L2. Pure Python + numpy, so
   the same code runs in training and in Satya on any laptop.
3. **Classifier**: L2 logistic regression (liblinear, class-balanced, each dataset weighted
   equally). Shipped as `config/text_model.npz` (hashed weights only: no text can be recovered)
   + `config/text_model.json` (thresholds, data sha256, licences).

## 2. Data (all open; downloaded by the script; nothing committed)

| Set | Channel | Licence | Raw | After template dedup | Test (fraud) | Notes |
|---|---|---|---|---|---|---|
| `zefang-liu/phishing-email-dataset` | e-mail | LGPL-3.0 | 18,647 | 17,169 | 2,576 (952) | phishing vs Enron-style ham |
| `tasksource/CLAIR_email_fraud` | e-mail | CC-BY-3.0 | 11,760 | 9,986 | 1,496 (609) | 419 / advance-fee fraud; official split, 367 official test rows that copied a train template removed |
| `codesignal/sms-spam-collection` (UCI) | SMS | CC-BY-4.0 | 5,567 | 5,100 | 765 (98) | |
| `CloveAI/india-spam-sms` | SMS | MIT | 20,010 | 5,296 | 795 (84) | 74 % of rows were template duplicates |
| `anmolshrivastav/scam_ham_india_14_languages` | SMS | MIT | 14,000 | 6,239 | 513 (216) | 14 Indian languages; official split, 879 / 1,400 official test rows copied a train template |

`template_key` = lower-case, digits → 0, URLs/e-mails → tokens, punctuation collapsed. Exact
template duplicates are dropped, a template labelled both ways is dropped, and splits are by
template group (70/15/15, seeded) or the official split minus leaked templates. Rebuilding the
table from the sha256-pinned raw files reproduces it exactly (`table_rebuild_identical: true`
in the manifest).

## 3. Protocol (fixed before the test run)

- **C** chosen by 5-fold `StratifiedGroupKFold` (groups = templates) on the union train split:
  CV AUC 0.9977 ± 0.0005 at C = 32 (grid 0.5–32; the curve is flat above 8: 0.9970 → 0.9977).
- **Thresholds** on the val split's legitimate texts: τ_hi = 1 % FPR (0.427), τ_lo = 5 %.
- **Test** split scored once. AUC/AP with a 95 % bootstrap over template clusters (2,000
  resamples); rates with Wilson 95 % intervals.
- **Comparators**: per-dataset specialists; **leave-one-dataset-out** (trained on the other six,
  thresholds from their val) = how the model does on a source it has never seen; the zero-shot
  ask lexicon (frozen v1.0 and the product path).
- **Robustness**: every fraud test text attacked with seeded, code-generated obfuscations
  (`research/text/attacks.py`), scored with and without the de-obfuscation layer (the "without"
  model is retrained without it, same C).

## 4. Results

**In-domain (union model, the one that ships), test AUC [95 % CI] and operating point at τ_hi:**

| Dataset | AUC | Caught (TPR) | False alarms (FPR) |
|---|---|---|---|
| phishing e-mail | 0.994 [0.991, 0.996] | 95.0 % [93.4, 96.2] | 2.6 % [2.0, 3.5] |
| CLAIR fraud e-mail | 1.000 [0.999, 1.000] | 98.2 % [96.8, 99.0] | 0.4 % [0.2, 1.1] |
| UCI SMS | 0.989 [0.976, 0.997] | 91.8 % [84.7, 95.8] | 1.2 % [0.6, 2.4] |
| Indian SMS | 1.000 [1.000, 1.000] | 100 % [95.6, 100] | 0.0 % [0.0, 0.5] |
| 14-language Indian | 1.000 [1.000, 1.000] | 100 % [98.2, 100] | 0.0 % [0.0, 1.3] |
| Hinglish calls (synthetic) | 1.000 | 100 % [96.1, 100] | 0.0 % [0.0, 18.4] (17 legit) |
| scam dialogues (synthetic) | 1.000 | 100 % [97.6, 100] | 0.0 % [0.0, 2.3] |

**Are the test texts just copies of training texts?** (`research/text/neardup.py`: highest cosine
of each test text to any training text.) Re-scored on the *novel* test texts only (no training
text with cosine ≥ 0.8), AUC is unchanged: phishing 0.991, CLAIR 1.000, UCI 0.987, Indian SMS
1.000, scam dialogues 1.000 (n = 298–2,159). Two sets are mostly near-copies even after
template dedup: 14-language Indian (68 % of test texts have a ≥ 0.8 neighbour; novel subset
n = 163, AUC 1.000) and Hinglish calls (96 %; only 4 novel texts), so their in-domain numbers
say little; read their leave-one-dataset-out row instead.

**Unseen source (leave-one-dataset-out), test AUC [95 % CI]:** CLAIR 0.982 [0.977, 0.988],
Hinglish calls 0.995 [0.983, 1.000], UCI SMS 0.856 [0.815, 0.893], Indian SMS 0.850
[0.815, 0.881], 14-language Indian 0.753 [0.708, 0.796], scam dialogues 0.725 [0.665, 0.780],
phishing e-mail 0.693 [0.671, 0.713]. A new channel or language costs a lot: this is the
number to quote for "a kind of message we never trained on", and why the classifier is
evidence capped at VERIFY rather than a verdict.

**Evasion (2,213 attacked fraud texts; 4,363 clean legitimate texts), TPR at the frozen τ_hi:**

| Attack | With de-obfuscation | Without |
|---|---|---|
| none | 97.0 % [96.2, 97.6] | 96.6 % [95.8, 97.3] |
| homoglyphs (30 % of letters) | 97.0 % [96.2, 97.6] | 72.9 % [71.0, 74.7] |
| leetspeak (40 %) | 96.9 % [96.1, 97.6] | 82.5 % [80.8, 84.0] |
| zero-width characters | 97.0 % [96.2, 97.6] | 95.8 % [94.9, 96.6] |
| spaced-out words | 96.8 % [96.0, 97.5] | 95.4 % [94.4, 96.2] |
| all four combined | **96.2 % [95.4, 97.0]** | **40.1 % [38.1, 42.2]** |

| 14-language Indian | 1.000 / 0.991 | **100 %** / 71.8 % | 0.753 / **0.901** |

Reading: on sources it has seen, the n-gram model is sharper (it catches 20–30 points more at
the same 1 % false-alarm target) and, with the de-obfuscation layer, far harder to evade; the
multilingual embeddings transfer better to a source or language they never saw (4 of 7 sets).
We ship TF-IDF (6 MB, pure numpy, any laptop) and keep the leave-one-dataset-out gap as a known
limit. A TF-IDF + embedding ensemble is the obvious next step; we did **not** pick one here
because the idea came after seeing these test numbers, and choosing on test would not be
defensible.

**Zero-shot ask lexicon** (does the message ask for money, an OTP, secrecy...?): AUC 0.50–0.74,
catching 0–49 % of scams. Most open "scam" sets are phishing/spam without an explicit payment
ask; the lexicon is built for the payment-instruction asks of BEC/impersonation and keeps its
own held-out benchmark (`results/EVIDENCE_LEDGER.md` §1).

## 5. What we do not claim

- In-domain AUCs near 1.000 mean these public sets are easy once seen, not that scams are
  solved: the leave-one-dataset-out row (0.69–0.99) is the honest generalisation number.
- Two of the seven sets are LLM-generated by their authors; no headline pools them.
- The per-dataset FPR at τ_hi varies (0–2.6 %) because τ is fitted on the pooled val split.
- No Indian bank/UPI message corpus with a clear licence was available; the Indian SMS sets
  are the closest open proxies.
