# M1 Design Note — Evidence Intake, Working-Copy Isolation & Cryptographic Custody

## 1. Objective
Establish the foundational forensic evidence locker (`src/satyapan/forensics/locker.py`) so that every piece of multimedia evidence is cryptographically sealed at intake, stored as a read-only original (`0o444`), tracked in an Ed25519-signed hash-chained custody log with an RFC 6962 Merkle tree root, and analysed exclusively via verified working copies.

## 2. Case Folder Layout
Each forensic case lives in an isolated directory `<cases_root>/<case_id>/`:
```
<case_id>/
  case_meta.json                 # case title, agency, examiner, created_at_utc
  originals/EV0001__<name>       # sealed copy, chmod 0o444 (read-only)
  working/EV0001__<name>         # mutable working copy used by detectors
  artifacts/EV0001/              # generated heatmaps, spectrograms, analysis JSON
  evidence.json                  # list of ForensicEvidenceItem records
  custody.jsonl                  # hash-chained + Ed25519-signed custody entries
  anchor.txt                     # paper-register anchor: case_id, chain_head, time, merkle_root
```

## 3. Cryptographic Guarantees (Adapted from Pramaan with Attribution)
1. **Hash Before Parse**: `sha256_file` streams the raw bytes before any parser or detector opens the file.
2. **Read-Only Originals & Working Copies**:
   - `intake(src, ...)` copies `src` into `originals/<evidence_id>__<name>` and strips write permissions (`0o444`).
   - `checkout_working_copy(evidence_id, actor, purpose)` verifies that the sealed file in `originals/` still matches its intake SHA-256 and `0o444` mode, copies it to `working/<evidence_id>__<name>`, logs a signed `"working_copy"` custody entry, and returns the working path. All M2–M4 detectors accept working-copy paths and assert they never read or mutate `originals/` directly.
3. **Signed Hash-Chained Custody Log (`custody.jsonl`)**:
   - `link = SHA-256(prev_link || canonical_json(body))` starting from `GENESIS_LINK = "0"*64`.
   - `signature = Ed25519.sign(link, examiner_private_key)`.
4. **RFC 6962 Merkle Tree & Inclusion Proofs**:
   - `leaf = SHA-256(0x00 || "<evidence_id>:<sha256>")`, `node = SHA-256(0x01 || left || right)`.
   - `audit_proof(evidence_id)` produces an $O(\log N)$ inclusion proof verified against `anchor.txt`.
