# `api/routes_forensics.py` + `forensics/pipeline.py` — the examiner's workstation

**What it does.** `pipeline.analyze_evidence_item` checks out a working copy and runs M2+M3+M4 for
that modality, then combines them into one non-absolutist verdict with a merged "why" and limitations
list. `analyze_case` persists `analysis.json`, builds the chronological timeline from metadata +
detector anomalies + custody events, and adds Merkle proofs. `routes_forensics.py` serves
`GET /forensics` (one self-contained HTML page, zero external assets) and the `/api/forensics/*` REST
API: cases, create, demo seeder, multipart intake, artifact PNGs, tamper simulation/restore, and
report download.

**Core idea.** An examiner needs to see *one case*, not a model zoo. Every finding is shown with a
confidence, a plain-language statement, the technical indicators behind it, the picture that shows it
(heatmap/spectrogram), and what the method cannot do. The custody tab lets them flip one bit of a
sealed copy and watch the integrity banner and Merkle proof fail, then restore it — so the integrity
claim is demonstrated, not asserted.

**Five questions a judge may ask**

1. *Where does the "why" come from?* Each detector returns structured `subchecks` and human-readable
   reasons; the dashboard renders them verbatim. Nothing is generated by an LLM, so nothing can be
   hallucinated.
2. *Is it really offline?* The page is served inline with no CDN, no external font, no telemetry. A
   test asserts the served HTML contains no external script/style URLs; the network invariant tests
   keep network imports inside `adapters/`.
3. *What happens when a detector is missing?* It abstains: the item JSON says
   `inconclusive_abstain` with a reason (e.g. "video decoder not installed"), never a pass.
4. *Can a maker/triage user see raw scores?* The dashboard is an examiner view. The policy invariant
   that makers never see raw scores still holds in the consumer/business product.
5. *Does uploading through the API preserve custody?* Yes: intake hashes first, seals read-only,
   checks out a working copy, logs signed `intake`/`working_copy`/`analyze` entries, and re-anchors.

**Weaknesses.** Single-user demo auth (no SSO). Large model files are optional, so on a bare install
the face/voice engines abstain. The timeline mixes claimed metadata times with real custody times and
labels them, but a forged EXIF time still appears on it (as a claim).
