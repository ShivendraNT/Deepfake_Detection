# T08 — Invoice / PDF checker

## Goal
Read the invoice PDF's text layer, extract IFSC / account / UPI / GSTIN / amount / invoice number
with regex, read PDF edit metadata, and compare with the vendor master. Output raise-only signals.

## Owner
Kartikey. Effort ≈ 4 h.

## Depends on
T01 (done). T03 helps (email attachments) but is not required for the tests.

## Files to create or modify
- `src/satyapan/document/extract.py` — `extract_invoice_fields` (patterns are given)
- `src/satyapan/document/pdf.py` — `extract_pdf_text`, `parse_pdf_date`, `read_pdf_metadata`
- `src/satyapan/document/checker.py` — `document_signals`

## Do not touch
Contracts, policy, tests, `data/demo/invoices/` (generated by `scripts/make_demo_data.py`).

## Interfaces
```python
extract_invoice_fields(text: str) -> InvoiceFields
extract_pdf_text(data: bytes) -> str            # ValueError if not a PDF
parse_pdf_date(value: str | None) -> datetime | None
read_pdf_metadata(data: bytes) -> PdfMeta       # eof_count, incremental_updates, producer, dates
document_signals(fields, meta, master, txn, evidence_id) -> DetectorOutput
```
Expected output for the 6 fixture PDFs: `data/demo/invoices/expected.json`, e.g.
```json
"inv_kaveri_edited_bank.pdf": {"vendor_id": "V001",
  "fields": {"ifsc_codes": ["FAKE0000620"], "account_numbers": ["99996666006200"], "upi_ids": [],
             "gstins": ["00FAKEV0001A1Z5"], "amounts_inr": [620000], "invoice_number": "KDP/2026/0920"},
  "eof_count": 2, "signals": ["DOC_ACCOUNT_MISMATCH", "DOC_PDF_EDITED"]}
```

## Plan (steps)
1. `extract_invoice_fields` on plain text (`test_regex_on_plain_text`, `test_phone_digits_not_account`).
   Accounts: search `ACCOUNT_DIGITS` only in the 40 characters after each `ACCOUNT_KEYWORDS` hit.
2. `extract_pdf_text`: `if not data.startswith(b"%PDF"): raise ValueError`; pdfplumber on
   `io.BytesIO(data)`.
3. `parse_pdf_date`: regex `D:(\d{4})(\d{2})(\d{2})(\d{2})(\d{2})(\d{2})([+-])(\d{2})'(\d{2})'`.
4. `read_pdf_metadata`: `data.count(b"%%EOF")`; info dict from `pdf.metadata`.
5. `document_signals`: vendor by `txn.vendor_id`, else by GSTIN match in `master.vendors`;
   rules in the docstring. Mask any account in `detail` (`mask_account`).
6. Run the fixture tests.

## Acceptance criteria
- 6 fixture PDFs (2 edited) → exact fields, EOF counts, and signals; edited ones flagged.
- Email addresses are not UPI ids; phone numbers are not accounts; no full account in `detail`.

## Common mistakes
- Treating `DOC_PDF_EDITED` as proof of fraud (it is weak; shown "inconclusive" alone).
- OCR / Textract — out of scope (Textract has no Hindi; MVP uses the text layer).
- Returning amounts as strings or with paise.

## Hints and links
- pdfplumber: https://github.com/jsvine/pdfplumber
- PDF incremental updates: each update appends a new `%%EOF` (PDF 1.7 spec §7.5.6).
