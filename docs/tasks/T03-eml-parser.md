# T03 — .eml parser

## Goal
Turn raw `.eml` bytes into a `ParsedEmail`: sender domains, the TRUSTED Authentication-Results
verdicts, a clean plain-text body (no hidden injection text) and attachment metadata.

## Owner
B2 (beginner). Effort ≈ 3 h.

## Depends on
T01 (done).

## Files to create or modify
- `src/satyapan/email/parser.py` — implement `parse_eml`, `parse_auth_results`, `extract_attachments`

## Do not touch
`src/satyapan/contracts/`, `tests/`, `data/demo/emails/` (fixtures are generated by
`scripts/make_demo_data.py`), any other module.

## Interfaces
```python
parse_eml(raw: bytes, *, trusted_authserv_id: str) -> ParsedEmail
parse_auth_results(header_values: list[str], trusted_authserv_id: str) -> AuthResults
extract_attachments(raw: bytes) -> list[tuple[str | None, str, bytes]]   # (filename, media_type, bytes)
```
`ParsedEmail` / `AuthResults` / `AttachmentMeta` are in `src/satyapan/contracts/parsed.py`.
Example (fixture `04_dmarc_fail_spoofed_cfo.eml`):
```json
{"from_addr": "rajesh@demo-industries.example", "from_domain": "demo-industries.example",
 "reply_to_domain": "gmail.com", "return_path_domain": "mailer-xyz.example",
 "auth": {"authserv_id": "mx.demo-industries.example", "spf": "fail", "dkim": "none",
          "dmarc": "fail", "trusted": true, "untrusted_headers_seen": 0}}
```
Expected values for all 10 fixtures: `data/demo/emails/expected.json`.

## Plan (steps)
1. `extract_attachments`: `email.message_from_bytes(raw, policy=email.policy.default)`;
   `msg.iter_attachments()`; `part.get_content()` bytes. Test: `test_attachment_sha256`.
2. `parse_auth_results`: iterate header values in order (top first). For each, authserv-id = text
   before the first `;` (strip). The FIRST value whose id equals `trusted_authserv_id` is trusted;
   regex `\b(spf|dkim|dmarc)=(\w+)` for verdicts. Every other value → `untrusted_headers_seen += 1`.
3. `parse_eml`: `msg.get_all("Authentication-Results", [])`; `email.utils.parseaddr` for
   From/Reply-To/Return-Path; domain = part after `@`, lower-cased. Raise `ValueError` if no From.
4. Body: prefer `msg.get_body(preferencelist=("plain",))`; else take the HTML, remove
   `<!-- ... -->` comments and elements with `display:none` (regex is fine for the fixtures), strip
   tags, unescape entities (`html.unescape`), collapse whitespace.
5. Attachments → `AttachmentMeta(filename, media_type, size_bytes, sha256)`.
6. `date`: `email.utils.parsedate_to_datetime`, `None` on failure.

## Acceptance criteria
- All 10 fixture emails produce the expected fields (`test_fixture_email[...]`).
- Topmost-trusted rule and attacker-added header handling (`05_fake_auth_header.eml`).
- Hidden HTML comment / `display:none` text never appears in `body_text` (`09_prompt_injection.eml`).
- Missing From → `ValueError`.

## Common mistakes
- Trusting the LAST or ANY `Authentication-Results` header. Only the topmost one with OUR id.
- Using `msg.get("Authentication-Results")` (returns only one header) instead of `get_all`.
- Keeping HTML comments in the body (prompt-injection leak).
- Returning `"None"` strings instead of `None` for missing Reply-To.
- Network/DNS lookups — not allowed and not needed.
